# Ryoshu

**領収書OCRとAIによる勘定科目候補の作成アプリ（各種CSV対応）**

個人事業主・フリーランス向けの、ローカルで動く領収書整理・経費帳アプリです。Indra OCR 1.1.2で画像やPDFを読み取り、別のローカルモデルQwen3 4Bが勘定科目の候補を提案します。デフォルトは、取り込んだ内容から未確認の帳簿を先に作り、あとから一覧で確認・修正する流れです。汎用CSVは未確認の明細も出力でき、確認後はfreee・MFクラウド・弥生へ取り込む形式で出力できます。

**AIの読取・科目は候補です。原本・金額・科目・用途は必ずご自身で確認し、税務上の最終判断は税理士に確認してください。** 「確認済み」は利用者による確認操作の状態で、税理士の承認や税法への適合を表すものではありません。[確認方針と提供範囲](docs/REVIEW-POLICY.md)

**v1.0.0**。Windows / Python 3.12 / CPUで確認しています。[リリースと配布ZIP](https://github.com/studio-yebisu/ryoshu/releases/tag/v1.0.0)

## できること

- **まとめて取り込み**：複数ファイル・フォルダーの選択とドラッグ＆ドロップ。1回2000ファイルまで選び、1ファイルずつ保存します。進捗、失敗理由、重複のスキップ結果が残り、一時停止・再開・失敗分の再試行もできます。
- **PDFの取り込み方を選択**：「1ファイルを1つの取引」は10ページまで、「1ページずつ別の領収書」は300ページまで。分割前の元PDFも保存します。JPG・PNG・WebP・PDFは1ファイル20MB、画像は2500万画素まで。
- SQLiteの38科目と15種類の確認条件による候補作成。科目の追加、支払先ルールの保存、用途不明の飲食・家事按分・資産候補の確認。
- **あとから確認**：原本・OCR本文・AI候補を比較し、経費帳の検索・期間・状態で絞り込めます。共通の用途・仕事の割合・支払元・税区分を空欄にまとめて入力し、原本を確かめて確認済みにできます。科目別集計、税込の仕訳、中断後の読み取り再開に対応します。
- **CSV出力**：汎用CSV、freee振替伝票、MFクラウド仕訳帳、弥生デスクトップ25項目形式。税区分や科目名の問題を保存前に表示し、CSV作成済みの版を除く出力も選べます。CSV作成履歴は会計ソフトへの取り込み完了を意味しません。
- **バックアップと復元**：原本・帳簿・修正履歴・分割前PDFをZIPに保存し、元の帳簿を上書きせず新しい保存先へ復元できます。

OCR・AIの候補はSQLiteに帳簿の下書きとして自動保存されます。確認を済ませなくても帳簿を作成・閲覧できます。未確定の金額・科目は空欄で残し、確認済みの仕訳とは区別します。あとから原本・業務用途・事業割合・支払元・税区分を確認し、共通項目を空欄へまとめて入力して確認済みにできます。設定で「1件ずつ確認してから帳簿へ並べる」にも切り替えられます。売上、口座照合、減価償却、決算・申告書の作成、返金・外貨の仕訳は対象外です。詳細は[帳簿の範囲](docs/GUIDE.md)を参照してください。

## 動作要件

| 項目 | 条件・確認範囲 |
| --- | --- |
| OS | Windows 11・64bitで動作確認。Windows 10、macOS、Linuxでのアプリ全体の確認は未実施 |
| Python | 3.12・64bit。uvがあればセットアップで3.12の環境を準備可能 |
| 起動環境 | Windows PowerShell 5.1以降、日本語フォント、JavaScriptが使えるブラウザー |
| AI実行 | [Ollama](https://ollama.com/download)と`qwen3:4b`。CPUで実行、専用GPUは不要 |
| メモリ | 最低容量は未測定。検証機はRAM 64GB搭載で、これは最低要件ではない |
| 空き容量 | 依存・OCR・LLMで初回に数GB。Qwenモデルは約2.5GB。領収書原本・バックアップの保存領域も必要 |
| 通信 | 初回の依存・モデル取得にネット接続。準備後のOCR・科目判断はPC内で実行 |

CPU・モデル版などの[確認済み環境と詳しい要件](docs/REQUIREMENTS.md)を掲載しています。

## 導入

**モデルの利用条件を先に確認してください。** アプリのコードはMITですが、IndraのOCR重みはmodified OpenRAIL-Mです。事業規模・資金調達額・提供元と競合する用途などに制限があります。重みとLLMは同梱していません。[ライセンスと依存元](THIRD_PARTY.md) / [OCR重みの原文](https://huggingface.co/datalab-to/indra-ocr/blob/bd02167fdf2005a19962cc15188f8496a2c87d3b/LICENSE)

[ソースZIPをダウンロード](https://github.com/studio-yebisu/ryoshu/archive/refs/heads/main.zip)して展開し、先にOllamaを導入します。Python 3.12・64bitまたはuvも用意し、展開したフォルダーの **`初回セットアップ.cmd`** をダブルクリックします。利用条件を確認して続けると、必要な環境とモデルを取得します。

準備後は **`Ryoshu.cmd` または `起動.cmd`** をダブルクリックします。[ローカル画面](http://127.0.0.1:8766/)が開きます。**`停止.cmd`** で終了、**`バックアップから復元.cmd`** で復元できます。Windows向けのローカルWebアプリで、単体のexeではありません。詳しい前提、終了方法、復元方法は[導入手順](docs/INSTALL.md)を参照してください。

## テスト画像と結果

[検証ページ](docs/testing/README.md)で、使った架空領収書の画像、元のPDF、期待値、修正前後の結果、残った差異、手動補正を確認できます。[比較CSV](docs/testing/comparison-100.csv)と[結果JSON](docs/testing/results.json)も同梱しています。アプリの「設定・保存」からも開けます。

公開済みv1.0.0の配布ZIPを固定し、100件すべてをHTTP取込・Indra OCR・ローカルモデルの勘定科目判定まで新規実行しました。[公開版100件の結果と残った差異](docs/testing/v1/README.md)。修正後は金額・円額未確定97/97、日付99/100、暫定科目47/48。返金3件は金額の分母から除外しています。**修正に使った同じ100件の回帰検査であり、未知の実物領収書の正答率ではありません。** 全指標と分母、期待値との判断差は検証ページに記載しています。

CSVは架空の6件を手動確認した別の検査で、4形式の生成・再読込と借貸の一致を確認しました。各会計ソフトの実アカウントへの取り込みは未実施です。

## 保存とプライバシー

保存先は既定で `%USERPROFILE%\StudioYebisu\ReceiptLedger`。SQLiteと原本はソースフォルダーの外に保存します。旧試作との互換性のため、内部のモジュール名と保存先名はReceiptLedgerを使用しています。

読み取り中の画像・本文を外部OCR・LLMへ送信する機能はありません。アプリとOllamaはループバック接続を使い、OCRは準備済みキャッシュから読み込みます。初回の依存関係・モデル取得は外部の配布元へ接続します。保存データとバックアップは暗号化していません。[保存範囲と通信](docs/PRIVACY.md)
