# 導入・更新・起動

[README](../README.md) / [動作要件](REQUIREMENTS.md) / [使い方](GUIDE.md)

## インストーラーから始める

1. [v1.3.4のWindowsインストーラー](https://github.com/studio-yebisu/ryoshu/releases/download/v1.3.4/Ryoshu-1.3.4-windows-x64-setup.exe)を入手して実行します。現在のWindows利用者へ配置するため、管理者権限は不要です。
2. 配布EXEにはコード署名がありません。Windowsに発行元不明と表示されたら、入手先がこのリポジトリのReleaseかを確かめ、同じReleaseの`SHA256SUMS.txt`でファイルを照合してください。
3. スタートメニューの「Ryoshu」を開きます。Ollamaが未導入なら案内から公式サイトへ進み、Ollama Windows版を導入してから開き直します。
4. モデルの利用条件を確認して初回準備を始めます。実行環境・Python 3.12.15・依存・OCRモデル・約2.5GBのQwenモデルを外部の配布元から取得するため、ネット接続と数GB以上の空き容量が必要です。
5. ブラウザーで復元用パスワードを2回入力し、保管の確認にチェックを入れます。パスワードは安全な場所へ保管してください。通常の起動ではWindowsが帳簿を開きます。

読み取りと科目候補の作成はローカルPC上で行いますが、初回準備には上記の通信が必要です。インストーラーにPython・Ollama・モデルは含まれません。初回準備では公式配布のuv 0.13.5を取得してSHA-256を照合し、続いて64bitのPythonと固定版ライブラリを専用の保存先へ用意します。手動でPythonやuvを入れる必要はありません。

依存・OCRモデル・Ollamaモデルの準備がそろってから完了を記録します。中断した場合は同じアプリから再試行してください。復元用パスワードを設定する前に閉じた場合も、次の起動で続きから設定できます。

モデルの条件は[THIRD_PARTY.md](../THIRD_PARTY.md)で確認できます。[v1.3.4の検証範囲](testing/v1.3.4/README.md)

## ソースZIPから始める

1. [配布一覧](https://github.com/studio-yebisu/ryoshu/releases/tag/v1.3.4)の`Ryoshu-1.3.4-source.zip`を新しいフォルダーへ展開します。
2. Ollama Windows版を導入し、`Ryoshu.cmd`をダブルクリックします。
3. モデルの利用条件を確認して初回準備を進め、ブラウザーで復元用パスワードを設定します。

初回準備だけをやり直す場合は`初回セットアップ.cmd`を使います。取得できない場合はネット接続・保存先・空き容量を確かめて再試行してください。準備後の読み取りで外部OCRや外部AIへ自動的に切り替わることはありません。

## 起動と終了

スタートメニューの「Ryoshu」、または`Ryoshu.cmd`・`起動.cmd`から開きます。起動リンクには、ローカルPC上のアプリを開くための短時間有効な認証情報が含まれています。アドレスを直接開いて「起動リンクから開いてください」と表示されたら、`Ryoshu.cmd`から開き直してください。

終了するときは、スタートメニューの「Ryoshuを終了」または`停止.cmd`を使います。ブラウザーを閉じるだけではアプリは終了しません。停止時にOllamaや帳簿ファイルは削除しません。別のアプリが8766番を使っている場合、そのアプリの停止や設定の上書きは行いません。

## v1.1〜v1.3系から更新する

旧版で暗号化バックアップを保存し、`停止.cmd`で終了します。新しいインストーラーを使うか、新しいZIPを別のフォルダーへ展開して`Ryoshu.cmd`を開いてください。同じWindows利用者と既定の保存先であれば、暗号化済みの帳簿を引き継ぎます。起動後に原本・件数・保存済みの修正を確認してください。

税額の扱いや科目候補に関する修正は、今後新しく読み取る候補へ適用されます。保存済みの入力や確認済みの仕訳を自動で書き換えません。古い未確認の候補を作り直す場合は個別に再読み取りし、原本と見比べてください。

v1.3.0からv1.3.4ではDBスキーマを変更しません。☆のよく使う科目は暗号化DBの設定に保存され、暗号化バックアップにも含まれます。☆の付け外しで明細・確認状態・仕訳は変わりません。

既定のインストール先は`%LOCALAPPDATA%\Programs\StudioYebisu\Ryoshu`です。スタートメニューには「Ryoshu」「Ryoshuを終了」「Ryoshuの導入ガイド」を作ります。デスクトップのショートカットは導入時に選択できます。

## アンインストールする

Ryoshuを終了し、Windowsの「設定」→「アプリ」から削除します。アプリとショートカットを削除しても、`%USERPROFILE%\StudioYebisu\ReceiptLedger`の帳簿・原本・復元用の情報・モデル・実行環境とOllamaは残ります。必要な暗号化バックアップは別の安全な場所にも保管してください。

## v1.0系から移行する

1. 旧版でバックアップを保存します。旧ZIPは暗号化されていないため、保存先を管理してください。
2. `停止.cmd`で旧版を終了します。
3. 新しい配布ZIPを別フォルダーへ展開し、`初回セットアップ.cmd`、続いて`Ryoshu.cmd`を実行します。
4. 復元用パスワードを設定し、移行の完了を待ちます。原本とすべての明細を照合してから切り替わります。
5. 内容を確認して新しい暗号化バックアップを保存します。

古いPython環境は`venv-before-update-*`として残ります。`data`、`restored`、`cache`を移動・削除しないでください。旧版では保護済み帳簿を開けません。原本の不足や不一致があれば切り替える前に止まります。[暗号化の説明](SECURITY-DESIGN.md)

v1.3では科目カテゴリーのためDBをスキーマ3へ更新します。更新前の暗号化スナップショットを保存し、明細・仕訳・独自科目を保持します。更新後のDBは旧アプリで開けません。旧版へ戻す場合は、更新前のバックアップを別の保存先へ復元してください。

## バックアップと復元

「設定・バックアップ」→「暗号化バックアップを保存」で、復元用パスワードを使う`.ryoshubak`を作成します。ファイルとパスワードは別々の安全な場所へ保管してください。Chrome/Edgeでは保存先を選べます。保存先を直接選べないブラウザーでは256MBまでです。

原本が不足・破損している場合は、救出用の設定で残ったデータだけを保存できます。省いた原本はそのバックアップから復元できず、不足件数は復元後にも表示されます。

復元は`バックアップから復元.cmd`から始めます。ファイルを選び、復元用パスワードを入力してください。旧ZIPの場合は新しい復元用パスワードを2回入力します。元の帳簿を上書きせず、新しい`restored/<日時と識別子>/data`へ復元します。後で開くときは、そのフォルダーの`この帳簿を開く.cmd`を使います。

Windowsで帳簿を開ける間は「設定・バックアップ」から復元用パスワードを再設定できます。過去のバックアップのパスワードは変わらないため、古いファイルの復元には作成当時のパスワードが必要です。再設定後は新しいバックアップを保存してください。

## 困ったとき

- **モデルへ接続できない**：Ollamaを起動します。`qwen3:4b`は初回セットアップで準備します。クラウド版や条件を満たさないモデルは拒否します。読み取りに失敗した明細は画面から再試行できます。
- **Pythonを起動できない・古い版が残る**：Ryoshuを`停止.cmd`で終了してから`初回セットアップ.cmd`を実行します。以前の実行環境は別名で残し、Ryoshu専用Pythonを用意します。
- **8766番が競合する**：案内に示された起動中アプリと接続先を確認します。別のアプリを自動では停止しません。
- **Windowsが帳簿を自動で開けない**：「復元用パスワードで帳簿を開く」で入力します。保護情報の破損・欠落や復元失敗時に、空の帳簿へ自動で切り替わることはありません。開けない場合は`バックアップから復元.cmd`でバックアップを選び、新しい保存先へ復元してください。
- **Windowsの鍵と復元用パスワードを両方失った**：帳簿を復元できません。開発者にも解除する方法はありません。

診断ログは`%USERPROFILE%\StudioYebisu\ReceiptLedger\runtime`にあります。実際の領収書・帳簿・復元情報・パスワード・バックアップを公開Issueへ貼らないでください。
