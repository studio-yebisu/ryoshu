# 導入・更新・起動

[README](../README.md) / [動作要件](REQUIREMENTS.md) / [使い方](GUIDE.md)

v1.3.4では、PowerShell 7のモジュール検索設定を引き継ぐWindows起動環境で、`Get-FileHash`が見つからず準備・起動が止まる問題を修正しました。ハッシュ照合を.NETの共通処理へ変更し、画面の日本語・余白・移動操作も整理しています。[今回の検証範囲と記録](testing/v1.3.4/README.md)

## インストーラーで導入する（おすすめ）

1. [v1.3.4のWindowsインストーラー](https://github.com/studio-yebisu/ryoshu/releases/download/v1.3.4/Ryoshu-1.3.4-windows-x64-setup.exe)をダウンロードして開きます。画面の案内に従って、このWindowsアカウント用にインストールします。管理者権限は不要です。
2. スタートメニューの「Ryoshu」から起動します。初回はPC内でAIを動かす[Ollama Windows版](https://ollama.com/download)の導入が必要です。未導入の場合は起動案内に従い、公式サイトから導入してください。
3. モデルの利用条件を確認し、コマンド画面でダウンロードを開始します。実行環境・OCRモデル・約2.5GBのQwenモデルを準備するため、ネット接続と数GB以上の空き容量が必要です。
4. ブラウザーが開いたら、復元用パスワードを2回入力し、「復元用パスワードを安全な場所に保管します」にチェックを入れて設定します。設定したパスワードは安全な場所に保管してください。次回以降はWindowsが自動で帳簿を開くため、毎回の入力は不要です。

インストーラーはアプリ本体を配置する導入用です。Python・Ollama・モデルは同梱しません。Pythonやuvを手動で用意する必要はありません。初回準備で公式配布のuv 0.13.5を取得し、ZIPと実行ファイルのSHA-256を照合してから使います。Python 3.12.15・64bitをアプリ専用の保存先へ取得し、バージョンとハッシュを固定した必要なライブラリを導入します。

必要なライブラリ・OCRモデル・Ollamaモデルの準備がすべて成功してから、初回準備の完了を記録します。途中で失敗した場合は、同じアプリから再試行して残りの準備を進めてください。最初の復元用パスワード設定前に閉じた場合も、再度起動して設定を続けられます。

配布EXEにはコード署名を付けていません。Windowsが発行元不明と表示する場合は、入手元がこのリポジトリのReleaseであることと、同じReleaseの`SHA256SUMS.txt`を確認してください。モデルの制限は[条件と原文](../THIRD_PARTY.md)で確認できます。

## ZIPから使う

1. [配布一覧](https://github.com/studio-yebisu/ryoshu/releases/tag/v1.3.4)の`Ryoshu-1.3.4-source.zip`を新しいフォルダーへ展開します。
2. Ollama Windows版を導入し、`Ryoshu.cmd`をダブルクリックします。
3. 初回のモデル利用条件を確認して準備を進め、ブラウザーで復元用パスワードを設定します。

初回準備だけをやり直す場合は`初回セットアップ.cmd`を使います。取得に失敗した場合は、ネット接続・保存先・空き容量を確認し、同じ手順で再試行できます。準備後の領収書処理は外部OCR・外部AIへ切り替えません。

## 毎回の起動と終了

スタートメニューの「Ryoshu」、またはアプリのフォルダーにある`Ryoshu.cmd`・`起動.cmd`から起動します。起動リンクにはこのPCのアプリを開くための短時間の認証情報が含まれます。アドレスだけを直接開いて「起動リンクから開いてください」と表示された場合も、`Ryoshu.cmd`から開き直してください。

終了するには、スタートメニューの「Ryoshuを終了」または`停止.cmd`を使います。ブラウザーを閉じるだけでは処理は終了しません。停止操作は対象のプロセスを照合し、Ollamaや帳簿ファイルは削除しません。別アプリが8766番を使っている場合は停止・上書きしません。

## v1.1〜v1.3系からv1.3.4へ更新する

旧版で暗号化バックアップを保存し、`停止.cmd`で終了します。新しいインストーラーで導入するか、配布ZIPを別のフォルダーへ展開して`Ryoshu.cmd`を起動してください。同じWindows利用者・既定の保存先なら、暗号化済みの帳簿を引き継ぎます。元のフォルダーや帳簿を上書き・削除する必要はありません。起動後は原本・件数・保存済みの修正を確認してください。

アプリ側の税額・科目に関する修正は、今後新しく読み取る候補に適用されます。保存済みの修正や確認済み仕訳を自動で書き換えません。未確認の旧候補に新しい読み取り処理を適用したい場合は、個別に再試行し、原本と見比べてください。

v1.3.0からv1.3.4ではDBスキーマを変更しません。よく使う科目のスターを既存の暗号化DB内の設定として保存します。付け外しによって保存済みの明細・確認状態・仕訳は変わりません。スターは暗号化バックアップにも含まれます。

インストール先は既定で`%LOCALAPPDATA%\Programs\StudioYebisu\Ryoshu`です。スタートメニューに「Ryoshu」「Ryoshuを終了」「Ryoshuの導入ガイド」を作成します。デスクトップのショートカットはインストール時に選べます。

## アンインストールする

Ryoshuを終了し、Windowsの「設定」→「アプリ」からRyoshuをアンインストールします。アプリとショートカットを削除し、`%USERPROFILE%\StudioYebisu\ReceiptLedger`の帳簿・原本・モデル・実行環境とOllamaは残します。帳簿の削除操作はアンインストーラーに含めません。必要なバックアップは別の安全な場所にも保存してください。

## v1.0系から更新する

1. 旧版でバックアップを保存し、安全に保管します。旧ZIPは暗号化されていません。
2. `停止.cmd`で旧版を終了します。
3. 新しい配布ZIPを別のフォルダーへ展開し、`初回セットアップ.cmd`、続いて`Ryoshu.cmd`を実行します。
4. 復元用パスワードを設定し、移行の完了を待ちます。原本とすべての明細を照合してから切り替えます。
5. 内容を確認して、新しい暗号化バックアップを保存します。

古いPython環境は削除せず `venv-before-update-*` として残します。`data`、`restored`、`cache`を移動・削除しないでください。旧版は保護済み帳簿を開けません。原本が不足している場合や内容が一致しない場合は、切り替え前に停止し、理由を表示します。[暗号化の説明](SECURITY-DESIGN.md)

v1.3は科目カテゴリーを保存するためDBをスキーマ3へ更新します。更新前の暗号化スナップショットを保存し、既存明細・仕訳・独自科目を保持します。更新したDBを旧アプリで開くことはできません。旧版へ戻す場合は、更新前のバックアップを別の保存先へ復元してください。

## バックアップ・復元

「設定・バックアップ」で「暗号化バックアップを保存」を選び、復元用パスワードを入力します。`.ryoshubak`を保存し、パスワードとは別の安全な場所へ保管します。Chrome/Edgeでは保存先を選んで書き込みます。保存先を直接選べないブラウザーでは、256MBまでのバックアップに対応します。

原本が不足・破損している場合は、救出用の設定で残ったデータだけを保存できます。完全なバックアップではなく、省いた原本はこのバックアップからは復元できません。不足件数は復元後にも表示します。

戻すときは`バックアップから復元.cmd`からファイルを選び、パスワードを入力します。旧ZIPも選べます。その場合は、新しい復元用パスワードを2回入力します。元の帳簿を上書きせず、新しい`restored/<日時と識別子>/data`へ復元します。復元後は、そのフォルダー内の`この帳簿を開く.cmd`から開けます。

パスワードを忘れても、Windowsで帳簿を開ける間は「設定・バックアップ」で再設定できます。**再設定しても、過去のバックアップのパスワードは変わりません。** その復元には作成当時のパスワードが必要です。再設定後は新しいバックアップを作成してください。

## 困ったとき

モデルに接続できないときはOllamaを起動します。クラウド版や不明なモデルは拒否します。`qwen3:4b`の準備は初回セットアップで行います。読み取りに失敗した明細は、画面から再試行できます。

Ryoshuが使うPythonを起動できない場合や、古いバージョンが残っている場合は、`初回セットアップ.cmd`で準備し直します。Ryoshuが起動中なら先に`停止.cmd`で終了してください。以前の実行環境は別名で保存し、Ryoshu専用Pythonを準備します。グローバルなuvのリンクや他アプリのPythonを手動で変更する必要はありません。8766番の競合が表示された場合は、表示された起動中アプリ・接続先を確認してから再試行してください。

Windowsが自動で帳簿を開けない場合は、「復元用パスワードで帳簿を開く」画面でパスワードを入力します。保護情報が破損・欠落している場合や、復元に失敗した場合も、空の帳簿へ自動で切り替えることはありません。バックアップから新しい保存先へ復元してください。

**Windowsの鍵と復元用パスワードの両方が使えなくなると、帳簿を復元できません。** 開発者にも解除する手段はありません。書き出したCSV・原本と旧版のZIPは暗号化されない通常のファイルなので、保存先・共有先を管理してください。

診断ログは`%USERPROFILE%\StudioYebisu\ReceiptLedger\runtime`です。実際の領収書、帳簿、復元情報、パスワード、バックアップを公開Issueへ貼らないでください。
