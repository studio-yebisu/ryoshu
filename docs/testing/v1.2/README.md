## 科目が保留になった原因

V021のタクシー領収書では、書類に単独で付けた「架空テスト」という識別表示を、AIが利用目的の記載として扱い、業務用途が分からないという理由で保留しました。単独の書類注記を科目判定用の入力から除き、**何の支出かの分類と、業務で使ったかの確認を分けました**。保存するOCR全文はそのまま残し、実際の商品名・サービス名に含まれる「テスト」等は除外しません。

文具・運賃・通信料金等は、用途が未入力という理由だけで科目候補を消しません。飲食、私用混在、家事按分、期間配分等の確認条件は残しています。事業概要を空欄にした追加5件と、全件共通の事業概要を指定した100件の両方で、V021は旅費交通費の候補になりました。この変更によっても、利用者による用途・経費性の確認は省略されません。

## 保護範囲と残る制約

今回も、外部AIを使わずローカルでOCR・科目候補・CSVを処理します。内部DB・保存済み原本・プレビュー・バックアップの暗号化方式はv1.1から継続しています。[実HTTP18項目](http-security.json)では未認証・異なるOrigin・不正Host等を拒否し、認証済みの原本・CSV・暗号化バックアップの入出力を確認しました。

依存ライブラリと同梱ネイティブコードの点検結果は、[v1.1時点の安全性点検](../security/README.md#依存ライブラリの点検と残る制約)と[ネイティブ依存の記録](../security/native-dependencies.json)を参照してください。これを今回の新しい全体監査や、脆弱性がないことの保証として扱いません。

書き出したCSVや原本は通常の平文ファイルです。同じWindowsアカウントの不正ソフト、管理者権限、開いた画面、OSの一時領域・移行前のディスク領域は保存時暗号化の保護範囲外です。[保護方式と制約](../../SECURITY-DESIGN.md)

新しいPCへのクリーンインストール、代表的な利用者による使いやすさ調査、会計ソフトの実アカウントへの取込は今回の検査対象外です。
