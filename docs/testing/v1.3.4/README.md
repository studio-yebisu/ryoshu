## 今回の修正

- PowerShell 7のモジュール検索設定を引き継いだWindows PowerShellで、`Get-FileHash`が見つからず準備・起動が止まる問題に対応しました。準備状態の記録とuvの検証は、共通の.NET SHA-256処理でファイルを順に読み取って照合します。
- 「読み込む」の作業領域と進捗カードを最大960pxに揃え、主ボタンの高さ44px・パネル内の基本余白20pxを共通化しました。
- 問題なく終了した進捗カードを読み取り結果・CSV出力などの作業画面では非表示にし、ホームでも原本の保存件数だけのカードは残しません。処理中・一時停止・失敗・接続不良・重複の案内は保持します。
- ナビゲーションによる移動時は、画面の先頭へスクロールして見出しへフォーカスします。明細の詳細から戻ると、元の画面・期間・検索条件・表示位置・明細ボタンのフォーカスを復元します。通常の進捗更新では入力や閲覧位置を動かしません。
- 完了したバッチの後に新しい取り込みを始める場合は、最初の応答を待つ猶予を設けます。サーバーから状態を取得した時刻は変えず、進行中のタイムアウトと実際の通信失敗は引き続き表示します。
- Kimi K3.1 Proによる公開ソースの文言レビューをもとに、画面・ヘルプ・導入手順の日本語を整理しました。ソースのレビューと、実画面での表示・操作の確認は別に扱います。

## 検証範囲の区別

Python本体の参照先が欠落した仮想環境の再現と、利用者が提示したエラー文面そのものの完全な再現は別です。今回の記録で、元のuvエラー文面が完全一致したとは扱いません。

隔離した新しいアプリ環境でも、既存のダウンロードキャッシュ・Ollama・モデルを利用する場合があります。これは初期状態の別PCでのクリーンインストール検証ではありません。CLIから起動した結果だけで、元のショートカットによる全初回準備・起動の成功とも扱いません。

新しい100件のOCR・AI精度検証は実施していません。科目マスター・OCR・勘定科目候補の生成方法・仕訳の計算と、画面や説明文の修正を分けて扱います。過去の正答数・差異・除外条件は、[v1.3.0の記録](../v1.3/README.md)を保持します。会計ソフト各社の実アカウントへのCSV取り込みは未検証です。
