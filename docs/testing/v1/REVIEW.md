# レビューと修正の対応

[v1の検証記録](README.md) / [モデル指定と実行記録](reviews.json)

公開候補を凍結して、Claude CodeのOpus 5.5、Kimi CodeのKimi K3、AntigravityのターミナルからGemini 3.8 Flashへ渡しました。対象はアプリの公開ソースと文書で、利用者の領収書や帳簿は渡していません。レビューはソースを読む検査です。実ブラウザー操作・OCR・AI推論・会計サービスへの取り込みとは別です。

## 指摘と対応

| 主な指摘 | 対応・確かめ方 |
| --- | --- |
| まとめて取り込めず、合本PDFの扱いも分からない | ファイル・フォルダー選択とドロップ、PDFの明示選択、元PDF保存、停止・再開・再試行を追加。100ファイルと100ページPDFの画面操作で確認 |
| PDF文字層や補正前OCRの返金根拠が確認時に抜ける | すべての保持根拠を確認条件に使用。AI停止時も含めた回帰テストを追加 |
| 日本語入力の変換中に検索欄が作り直される | 入力欄を保持し、変換終了後に表だけ更新。ブラウザーの変換イベントとフォーカスを確認 |
| 初回の手順、失敗理由、確認済みにできない理由が見えにくい | 0件時の案内、具体的な日本語エラー、常時表示する停止理由、詳細を開く前のPDFやり直し案内を追加 |
| 一括確認後、残った明細をたどれない | 名前付きの結果をタブ内で保持。残った明細だけの絞り込みを追加し、明細を開いて戻る操作を確認 |
| CSVのGETだけで履歴が変わる | GETを参照専用にし、作成履歴は保護したPOSTで記録。未確認・出力済み・修正版も別に検査 |
| CSVプレビュー失敗後も保存ボタンが押せる | 計算中と失敗時は無効化。通信失敗と復帰をブラウザーで確認 |
| バックアップがメモリを大量使用し、復元後のプレビューもない | ディスク上でZIPを作成して配信。復元先を新規に限定し、原本照合後にプレビューを必要時に再生成 |
| 同じページが複数の元PDFにあると保存関係が欠ける | 多対多の対応表に変更し、移行前スナップショットを保存。両方の元PDFがバックアップに残ることを確認 |
| 1ページPDFの取り込み方を変えると二重になる | 元のバイト列を使用し、同じ明細として扱う検査を追加。複数ページPDFを意図して取り込み直す操作とは区別 |
| PDFiumの並行処理、画像検査の待ち、似た明細の大量警告 | PDFiumは共通ロックで保護。画像の形式検査はそのロックから分離。警告の参照数を制限し、詳細では軽い重複照合を使用 |
| 停止時の接続情報が配列だと例外になる | PIDを重複除去し、すべて照合してから停止。架空プロセスだけを使うWindows PowerShell検査で、正常系と無関係な接続の拒否を確認 |

## 採用しなかった指摘・確認範囲

Kimiの初回レビューには「2030年10月以降の30%経過措置は存在しない」という指摘がありました。[国税庁の令和8年度税制改正資料](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/invoice-review/index.htm)と照合し、採用していません。アプリが各取引への税区分の適用可否を自動判断するものではありません。

一括の「確認済みにする割合を0%も許可する」という案も採用していません。私用分だけの明細は対象外にし、確認済みにする事業分は1〜100%とする契約を維持します。入力済みの0%を一括入力で100%へ書き換えないことも検査しています。

一覧のOCR JSON解析負荷は、2000件の合成DBで測定しました。今回の測定と軽い重複照合の結果は[検証記録](README.md#大量データの測定)に載せ、処理速度を保証する説明にはしていません。実測の根拠なくDBの列・移行を増やす案は見送っています。

最初のOpusによる公式ヘルプ調査は、無料でWeb取得するツール（treg）を使いました。その時点では指定名の「イモズル」スキルを発見できていませんでした。その後、正式名imozuruの実ファイルを特定し、Opus 5.5による[原典調査と抜き書き照合](RESEARCH.md)を追加しました。モデルの利用枠とWeb取得の費用は別です。

Opusの途中の再レビュー1回はCLIのターン数上限で終了しました。完了扱いにせず、同じ指定モデルへソースを直接渡した再レビューで報告を取得しています。Kimiの追加再レビューも取得し、二重起動とPDF分割失敗の指摘を修正しました。最新差分について、Kimi K3・Gemini 3.8 Flash・Opus 5.5はいずれも新規の再現可能なコード上の公開阻害はないと報告しました。凍結時点の文書の検査数が古いという指摘は、119件・5本へ更新し、実行結果と照合しています。元の100件の数値は更新していません。

Pillowの「警告が上限の半分で出る」というKimiの指摘も、[公式資料](https://pillow.readthedocs.io/en/stable/reference/Image.html)と使用中の13.0.0の実装と異なるため採用していません。警告は設定上限を超えた場合、例外はその2倍を超えた場合です。1400万画素の受け入れと2600万画素の拒否を実画像で検査しました。アプリの上限は2500万画素のままです。

起動・終了は共通のファイルロックで同時操作を防ぎ、起動成功後に実際の待受PIDを記録します。記録がない・古い場合も、専用venvまたは照合済みの親プロセスを確認できる場合だけ復旧します。実際の利用者のプロセスはテストで停止していません。

その後、空の検証用帳簿と実際の専用venvで、起動・起動済み検出・接続記録の欠落からの復旧・終了を確認しました。元の帳簿には接続せず、終了後もOllamaと100件検証用の別サーバーが継続することを確認しています。

GitHub ActionsではWindowsの文字コードと、進捗の再描画で一時停止ボタンが取り外される問題が分かりました。文字コードをUTF-8に固定し、操作ボタンと保存済みの結果行を保持して更新する形へ修正しました。ブラウザー検査では強制クリックを使わず、取り込み中に同じボタン要素が維持されることも確認します。
