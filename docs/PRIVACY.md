# 保存データと通信

アプリは`127.0.0.1`にのみ待ち受け、OCRと取り込み時の科目判断は、このPCと`127.0.0.1:11434`のOllamaで行います。監査フックで通常の外向き接続・DNS照会を拒否し、OCRはダウンロード済みキャッシュだけを使います。クラウドへの自動フォールバックやアクセス解析はありません。

開発版では、任意の[ChatGPTによるチャット編集](CHAT-EDIT.md)を追加しています。利用者が接続・送信を選んだ場合、選択した明細の入力項目・識別ID、登録済み科目名・説明、会話をOpenAIへ送信します。画像・PDF・OCR本文・選択外の明細・設定の事業概要は送りません。この処理中だけ、当該処理のスレッドが`auth.openai.com`と`api.openai.com`の443番ポートに接続できます。チャットを使わなければ、外部の推論を使わずに利用できます。

セットアップ時のパッケージ・モデル取得にはネット接続を使います。ブラウザーやOllama自体の更新確認を止める仕組みではありません。

既定では`%USERPROFILE%\StudioYebisu\ReceiptLedger\data`に、SQLite、領収書原本、分割前の元PDF、プレビューを保存します。SQLiteにはOCR本文、元のAI候補、利用者の修正、事業概要、支払先ルール、確定仕訳、変更履歴、CSV作成履歴も含まれます。OCRモデルは同階層の`cache`、LLMはOllamaのモデル保存先です。

バックアップには帳簿DBと原本・分割前の元PDFを含めます。復元して使う保存先は`runtime/data-location.json`に記録します。プレビュー画像はバックアップに含めず、必要になったときに原本から作り直します。OCR・AIを再実行する必要はありません。

チャットの会話は実行中のメモリにだけ保持します。検証済みの編集案、適用前後の値、変更履歴はSQLiteに保存され、バックアップにも含まれます。期限切れの未適用案は次の案の作成時に削除します。OAuthの認証情報は別の`auth`フォルダーへ保存し、WindowsではDPAPIで保護します。認証情報は帳簿DBやバックアップに含めず、ブラウザーにも返しません。

このアプリはデータやバックアップZIPを暗号化しません。PCのアカウント・ディスク・バックアップ先の権限で管理してください。CSVにも取引内容が入ります。サーバーをLANやインターネットへ公開する構成は対象外です。

同梱の`samples/receipts-100-v2`と`docs/testing`は架空の検証用データです。実際の利用者の領収書、DB、モデル、キャッシュ、端末固有の実行ログを公開リポジトリへ含めません。
