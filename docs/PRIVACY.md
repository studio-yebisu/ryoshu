# 保存データと通信

Ryoshuは領収書を外部AIへ送らず、PC内のIndra OCRとQwen3 4Bで処理します。外部AIのAPIキー・OAuth連携・クラウドへの自動切替・アクセス解析はありません。アプリは`127.0.0.1`だけで待ち受け、モデル接続先は`127.0.0.1:11434`のOllamaです。

本文を送る前に、モデルがローカルGGUFのQwen3であり、リモート転送先を持たないことを確認します。アプリが新たに起動するOllamaではクラウド機能を無効にします。既に動作中のOllamaやブラウザーの更新設定は変更しません。

アプリのPythonプロセスは監査フックで外向きTCP・UDP・DNSを拒否し、OCRは準備済みのキャッシュを使用します。これはOS全体やネイティブコードを隔離する完全なサンドボックスではありません。モデルサービス自体を別のプログラムへ差し替えた環境は対象外です。

初回準備はGitHub・Python依存の配布元・Hugging Face・Ollamaのモデル配布元へ接続します。ブラウザーで外部の資料リンクを開く操作、ブラウザーやOllama自体の更新は別です。「準備後に領収書を外部AIへ送らず処理する」ことと、PC全体で通信が一切起きないことは区別してください。

既定の帳簿保存先は`%USERPROFILE%\StudioYebisu\ReceiptLedger\data`です。SQLCipherのDBにOCR本文・元のAI候補・利用者の修正・事業概要・支払先ルール・仕訳・変更履歴・CSV作成履歴を保存します。原本・元PDF・プレビューも暗号化します。OCRモデルは`cache`、QwenはOllamaのモデル保存先にあり、領収書はモデルの重みに学習させません。

バックアップはパスワードで暗号化します。プレビューは含めず、復元後に原本から再作成します。書き出したCSV・原本、旧版のZIPは暗号化されない通常のファイルであり、保存先・共有先を利用者が管理してください。Ollama自身の診断ログやOSのログは、Ryoshuの帳簿暗号化には含まれません。

OCRと旧ZIPのDB変換は利用者専用の一時作業領域を使います。終了・例外時に片付けますが、強制終了で残る場合があります。OSのスワップ・クラッシュダンプ・以前の平文領域・同じWindows利用者の不正ソフト・開いた画面の操作は保護できません。[暗号化の仕様・復元・制約](SECURITY-DESIGN.md)

公開の`samples`と`docs/testing`は架空の検証用データだけです。実際の利用者の帳簿・領収書・鍵・キャッシュ・端末の実行ログを公開リポジトリへ含めません。開発時の外部モデルによるソースレビューと、アプリ実行時の領収書処理も区別します。[今回の点検結果](testing/security/README.md)
