# Ryoshuの使い方

個人事業主・フリーランス向けの、PC内で動く領収書整理・経費帳アプリです。

Indra OCR **1.1.2（1.1系）**で画像・PDFを読み取り、別のローカルモデル **Qwen3 4B / Q4_K_M** が購入内容と勘定科目の候補を作ります。取り込むと未確認の帳簿を先に作り、あとから原本と候補を見比べて確認・修正します。

金額・科目・用途などは、原本と照合して必ずご自身で確認してください。税務上の最終判断は、申告・税務処理に使う前に税理士に確認してください。「確認済み」は利用者の確認操作を表し、税理士の承認や適法性を表すものではありません。[確認方針](REVIEW-POLICY.md)

## 起動する

リポジトリ直下の **`Ryoshu.cmd` または `起動.cmd`** をダブルクリックしてください。

- 画面：<http://127.0.0.1:8766>
- 終了：`停止.cmd`をダブルクリック
- 初回準備：`初回セットアップ.cmd`をダブルクリック

初回は[導入手順](INSTALL.md)に従って準備してください。初回セットアップは公開の配布元から依存関係・OCR重み・約2.5GBのQwenモデルをダウンロードします。課金APIや外部推論サービスは使いません。

## 使い方

画面上部の「読み込む」「読み取り結果」「CSV出力」の順に進みます。科目別の集計、勘定科目一覧、設定・バックアップは「その他」から開きます。

1. JPG・PNG・WebP・PDFをドロップするか、ファイル・フォルダー選択から追加し、**「読み取りを開始」**を押します。一度に2000ファイルまで選べ、1ファイル20MBまでです。原本の保存が終わるまではタブを開いておきます。PDFの初期値は「1ファイルを1つの取引」（10ページまで）です。スキャンした領収書の束は、開始前に「変更」を開いて「1ページずつ別の領収書」（300ページまで）へ切り替えます。分割前の元PDFも保存します。1ページ内の複数の領収書の切り分けは未対応です。
2. OCR・AIの候補を暗号化DBへ自動保存します。**「読み取り結果を見る」**を開くと、原本画像・読み取った文字と数字・勘定科目が3列に並びます。画像をクリックすると拡大でき、倍率とページを切り替えられます。「読み取った文字を見る」でOCR全文を表示します。読み取り中や未確定の項目も区別して表示します。
3. 一覧の**「確認・修正する」**から原本と照合して修正します。「CSV出力」画面では、明細を選び、共通の用途・事業割合・支払元・会計ソフト出力用税区分を空欄へまとめて入力して確認済みにもできます。入力済みの内容は保持します。不足や更新競合がある明細は理由を表示して未確認のまま残します。
4. 作成直後の未確認を含む帳簿は汎用CSVで保存できます。会計ソフト向けの仕訳CSVには、確認済みの明細を出力します。帳簿の下書きと確定仕訳は区別して保持します。
5. CSV→freee、MFクラウド、弥生などに取り込みます。件数、行数、借貸合計と先頭の行を確認して保存します。各サービスの実アカウントへの取込検証は未実施です。詳しくは[CSV出力](CSV-EXPORT.md)を参照してください。

設定の「1件ずつ確認してから帳簿へ並べる」を有効にすると、確認後に帳簿へ進む流れへ切り替えられます。デフォルトは無効です。原本と読取結果が失われる切替ではありません。

設定の「事業の概要」は、次回のAI分類に使います。登録時に「この支払先の科目を次回の候補にする」を選ぶと、その支払先の科目をローカルに記憶します。

再読取では、既存の入力内容を保持して新しいAI候補を別に保存します。新しい候補を使う場合は「AI候補を入力欄へ戻す」を押します。用途・割合・支払方法は保持します。

同じファイルはSHA-256で検出して重複登録を防ぎます。違う写真でも日付・支払先・金額が一致する場合は「重複の可能性」を表示します。別の支出が同じ内容になる場合もあるため、自動では削除しません。

「設定・バックアップ」から、100種類の架空領収書PDFをダウンロードできます。Kimi K3・GPT-6.1 Sol・DeepSeek V4.1 Flashの通常版と1017固定版・Claude Sonnet 5.5・Claude Opus 5.5が、分野を分けて独立した帳票を設計しました。電子PDF48件に加え、傾いたスキャン18件・薄い印字12件・FAX8件・斜め撮影10件・回転4件です。ZIP内の個別PDFをまとめて選択できます。100ページの合本も、「1ページずつ別の領収書」で取り込めます。画像一覧・検索は同梱の `gallery.html`、期待値・業務背景・作成モデル・修正記録は `manifest.json` と `sources/` にあります。正解データはOCRや科目モデルの入力へ混ぜません。

## 勘定科目のデータベース

「勘定科目」画面で、SQLiteに保存された科目、用途の例、別名、品目の手がかり、確認事項、参照資料を見られます。独自の経費・資産科目も追加できます。

初期データは38科目（経費28、資産5、支払元・事業主勘定等5）と15種類の確認条件です。領収書の登録先として選べるのは経費・資産の33科目です。科目名と用例はアプリの編集データであり、税務上の取扱いを一律に確定する表ではありません。

1領収書につき1つの経費・資産科目を扱います。補助科目の管理・内訳集計、1枚の領収書の品目を複数科目へ分ける機能はありません。必要な場合は、原本と汎用CSVを使って会計ソフト側で設定・分割します。[科目を細かく分ける考え方と対応範囲](ACCOUNTS.md)

1. Indra OCRの行情報を座標で整え、金額とラベルを対応させます。PDFの文字層はIndraが画像との一致を確認した場合だけ参照します。斜めの紙面の補正や金額周辺の部分再読取も行い、元の本文と再読取の記録を保持します。
2. データベースの品目辞書で候補を絞ります。一致がなければ全選択可能科目から提案します。
3. QwenがDBの候補内から科目名と短い理由を返します。購入品、店名、日付、金額は独立して扱います。日付や金額は原文の根拠で照合し、記載額が複数ある場合だけ、モデルがその候補から今回分を選びます。
4. 用途不明の飲食、混在した購入、資産検討、家事関連費等の確認条件を適用します。返金等は通常の正の経費として登録できません。
5. 人が確認して登録すると、科目コードを参照した仕訳明細を保存します。貸借の一致を確認し、修正時は以前の仕訳を無効の履歴として残します。

確認済み取引を下書きに戻すと、以前の仕訳は集計から外れます。再登録時に新しい版の仕訳を保存します。支払先ルールは店舗名だけでなく購入内容も照合し、その後に確認条件を再適用します。

## 保存先とプライバシー

既定の保存先は **`%USERPROFILE%\StudioYebisu\ReceiptLedger`** です。

| 場所 | 内容 |
| --- | --- |
| `data/ledger.enc.sqlite3` | SQLCipherで暗号化した科目マスター、領収書、OCR本文、候補、仕訳、履歴、設定 |
| `data/ledger.sqlite3` | 旧版が空の帳簿を作らないためのガード。帳簿データは含みません |
| `data/receipts/<ID>/original.*` | 暗号化した原本 |
| `data/receipts/<ID>/preview-*.jpg` | 暗号化したプレビュー |
| `cache/` | OCRのモデルキャッシュ |
| `venv/` | このアプリ専用のPython環境 |
| `runtime/` | 起動情報とサーバーの診断ログ。領収書本文のログ出力は行いません |

DBスキーマは2です。主なテーブルは `account_master`、`account_policies`、`account_sources`、`receipts`、`journal_entries`、`journal_lines`、`merchant_rules`、`audit`、`settings`。アプリのDB接続では外部キー制約を有効にし、仕訳と科目コードの参照を検査します。

v0.1.0のDBを初めて開くときは、`data/backups/before-catalog-v2-*.sqlite3` に変更前のスナップショットを保存してから移行します。原本、既存の入力、支払先ルールと設定を保持します。登録済み明細には同じ内容の仕訳を作成します。

科目の初期データを更新したときは、既存の未確認明細に新しく合致する確認条件を候補と注意事項へ反映します。利用者の入力と確認済み仕訳は変更せず、更新前の候補は履歴に残します。過去の保留の解除や、弱めた・削除した条件による自動再推論は行いません。必要な場合は「再読取・AIを再実行」で新しい候補を取得し、原本と見比べて採用してください。

Qwen3のモデルはOllamaのモデル保存先に置きます。このPCではユーザープロファイルの `.ollama/models` です。ComfyUIの環境は使いません。

アプリは `127.0.0.1` にだけ待ち受けます。OCRはダウンロード済みキャッシュのみを使い、AIの呼出先は `http://127.0.0.1:11434` に固定しています。アプリのPythonプロセスには外向きの接続・DNS照会を拒否する監査フックも入れています。Ollamaやブラウザー自体の更新確認を停止する仕組みではありません。

画像と本文を外部のOCR・LLMへ送る機能、クラウドへの自動フォールバック、解析用のアクセス計測はありません。帳簿・原本・プレビュー・バックアップを暗号化します。書き出したCSV・原本や旧版ZIP、PCのアカウントは別途管理してください。[保護範囲](SECURITY-DESIGN.md)

## 帳簿と仕訳の範囲

- このアプリは**支出の経費帳と税込の経費仕訳**を作ります。売上、期首残高、口座・カード引落の照合、決算書、確定申告書は対象外です。
- 個人のお金で立て替えた支出は、事業分だけを `経費科目 / 事業主借` とします。
- 事業用の現金・預金・カードの共用支出は、事業分を経費科目、私用分を事業主貸に分けます。カードの貸方は未払金です。後日の引落仕訳は別途記録してください。
- 事業割合による1円未満の端数は四捨五入します。割合自体の妥当性は利用実態から確認してください。
- 工具器具備品・ソフトウェア・前払費用など、マスターで資産に分類した科目は経費の合計から分けます。減価償却や少額資産の特例判定はしません。仕入高の期末棚卸・売上原価の計算も別途必要です。
- 税率・税額・登録番号は原本の記載欄です。8%・10%の混在を保持できますが、税率別内訳や仕入税額控除、消費税申告額は計算しません。登録番号の公的照会もしません。
- 返金・返品・取消、外貨、複数取引の分割仕訳は未対応です。
- 電子帳簿保存法の要件を満たすことを認証・保証する製品ではありません。

利用中の科目・確認条件の正本は各利用者のSQLite DBです。新しいDBの初期データは `data/account-catalog.json` にあります。初期値の更新では、以前の初期値と一致する項目だけを更新し、利用者が修正した項目や追加した科目を保持します。経費にできるかは支出と事業の関係で決まるため、科目名の一致だけで確定しません。考え方は[国税庁「必要経費の知識」](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/2210.htm)と[減価償却のあらまし](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/2100.htm)を参照しています。

## OCR・AI候補の扱い

OCRの誤読はあり得ます。AIはOCR本文を解釈するため、元の誤読まで正せるとは限りません。候補の日付・支払先・金額の根拠をOCR本文と照合し、根拠がない値は空欄に戻します。AIの自己評価は正解率ではありません。

文具・交通運賃・通信料金などは、用途が未入力でも支出の種類から暫定の科目候補を作ります。仕事に使ったか、事業割合、支払元は自動で確定しません。帳票の見本表示や識別用の注記は、購入内容や利用目的と分けて扱います。

用途不明の飲食では会議費・接待交際費の候補を保留します。飲食の業務目的や相手、事業割合、支払元は本人が入力します。確認操作前でも帳簿の下書きを作成します。確認済みの仕訳は、あとから確認した明細で作成します。

PDFは取り込み時に、1ファイルを1件の支出として扱うか、1ページずつ分けるかを選びます。1ファイルを1取引にする場合は10ページまで、ページごとに分ける場合は300ページまでです。1枚に複数のレシートを置いた画像は、取り込み前に分割してください。

## バックアップと復元

「設定・バックアップ」から暗号化バックアップ `.ryoshubak` を保存します。復元用パスワードを入力してください。原本・帳簿・修正履歴・元PDFを含み、モデルとPython環境は含みません。

戻す場合は、アプリフォルダーの`バックアップから復元.cmd`をダブルクリックしてバックアップを選び、復元用パスワードを入力します。旧ZIPの場合は、新しく設定するパスワードを2回入力します。展開先は新しい`restored/<日時と識別子>/data`です。全体の認証、構成、帳簿、原本のSHA-256を確認し、元の帳簿は上書きしません。完了後に、復元した帳簿へ切り替えて起動するか選べます。次回の通常起動も選んだ保存先を使います。

その場で起動しなくても、復元結果のフォルダーに作る`この帳簿を開く.cmd`から後で開けます。別の帳簿が起動中なら、先に元のアプリフォルダーの`停止.cmd`で終了してからダブルクリックします。アプリのソースフォルダーを移動した場合は、元の場所へ戻すか、復元手順で新しい起動ファイルを作成してください。

復元した保存先が見つからない場合は、空の帳簿へ自動で切り替えずに停止します。復元を完了できなかったフォルダーには`RESTORE_FAILED.txt`を残し、使用中の保存先にはしません。復元機能は展開後20GBまでに対応します。

復元用パスワードを忘れた場合は、Windowsで開けるうちに「設定・バックアップ」で再設定し、新しいバックアップを保存してください。以前のバックアップには以前のパスワードが必要です。原本が不足・破損した場合の救出用バックアップは、不足を明示して残ったデータを保存します。復元後も不足件数を表示し、同じ原本を取り込み直すことで修復できます。
